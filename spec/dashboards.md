# Dashboards

`uv run aao serve` serves `dashboard/index.html` at <http://127.0.0.1:8765/> and runs the collectors in the background (machines every 60 s, quotas every 5 min, usage every 10 min). Snapshots go to `state/` (gitignored); committed data lives in `data/`. `uv run aao collect [machines|quotas|usage]` runs one collector from the shell.

| Tab | Source | Module |
| --- | --- | --- |
| Projects | `projects/*.json`: GitHub Project link, parent repo, owned submodule tree, external references | `projects.py`, [spec/github_project.md](github_project.md#project-configs) |
| Machines | herdr + SSH probe + cloud task lists | `machines.py`, `probe.py`, [spec/machines.md](machines.md) |
| Quotas | CLI status screens → Copilot entitlement API → quota-cli → Codex logs; web usage pages (Muse) | `quotas.py`, `quota_screens.py`, `web_muse.py` |
| Tokens & cost | local session logs on every machine, priced from the price table | `usage_scan.py`, `usage.py`, `pricing.py` |
| Free tokens | `data/free_tokens.json` | `free_tokens.py` |
| API prices | `data/api_prices.json` | `pricing.py` |

## Quotas (5-hour, weekly, monthly windows)

- **CLI status screens** are the primary source (below): every installed agent with `quota_screen` in `agents.json` (Claude, Codex, Cursor, Kiro, Antigravity) is read directly from its own built-in quota command.
- **GitHub Copilot** has no quota screen in its CLI, so `quotas.collect_copilot_accounts` reads the entitlement document the Copilot IDE extensions and CLI use (`GET https://api.github.com/copilot_internal/user`) with the signed-in `gh auth token` (falling back to `GH_TOKEN`/`GITHUB_TOKEN`). Each limited `quota_snapshots` entry (Premium requests, Chat, Completions) becomes a **monthly** window scoped by its name, with `used`/`remaining`/`limit` counts and `resets_at` from `quota_reset_date_utc`; unlimited quotas and quotas the plan does not include (entitlement 0) are skipped, never shown as 0 % or 100 %. The plan chip comes from `access_type_sku` (Free, Pro, Pro+, Business, Enterprise). It is a read-only GET; no token is stored or refreshed. A failure appears in Collector messages and leaves any quota-cli Copilot row in place. `AAO_QUOTA_COPILOT=0` disables it.
- **quota-cli** (`cargo install quota-cli`) is optional and covers Grok and Kimi, which have no supported quota screen (and Copilot when the API read fails). It reports *remaining* %, converted to used %. A readable status screen replaces quota-cli's row for the same provider and account; if the screen fails, the quota-cli row stays.
- **Codex session logs** carry `rate_limits` (primary = 5 h, secondary = weekly), read without any network call, when no Codex screen was read.
- DeepSeek and Devin are never shown (`quotas.EXCLUDED`).
- **CLI status screens**: `quota_screens.read_quota("claude")` opens Claude Code and runs its built-in `/usage`; `read_quota("codex")` runs `/status`. Each read uses a private herdr workspace, submits no natural-language prompt, waits for stable quota windows, and closes only that workspace. If the slash-command menu swallows the Enter (seen with Cursor about once in ten reads: the command stays typed in the input with its menu open), the reader presses Enter again, at most twice, and only when both the typed command and its menu entry are on screen. Startup screens follow the existing literal `startup_forms`; login screens are never answered. Other CLIs can be added with a verified built-in command in `agents.json` `quota_screen` and a parser in `quota_screens.py`. Local collection uses every installed CLI with that metadata; `AAO_QUOTA_SCREEN_AGENTS=claude,codex` limits it, and `none` disables it. Configured local account homes use `accounts.launch_spec`; the Python reader also accepts a saved herdr `machine` and its remote `cwd` for explicit remote reads. The dashboard collector currently reads local quota screens only.
- Screen percentages labelled **left/remaining** are converted to used percentage. Context-window percentages and token totals are ignored.
- **Reset times.** Every window carries `resets_at` (UTC) when its reset can be read, and keeps the screen's own words in `reset_text`. `quota_screens._reset` handles ISO timestamps, relative durations (`in 2d 3h`, `Refreshes in 22h 29m`), and local labels via `clock_reset`: clock times (`4pm`, `16:00`), clock plus date (`Nov 28, 8pm`, `12:38 AM on 24 Nov`) and dates (`Dec 5`, `2026-12-01`). A trailing IANA zone such as `(America/Vancouver)` is honoured (on Windows through the `tzdata` package); otherwise the collecting machine's zone is used, which is correct because screens are read locally. A missing year or day picks the next occurrence. A date without a clock time (Kiro, Cursor) is taken as local midnight and marked `reset_estimated`, shown with `~`. A label that matches none of these stays as `reset_text` only. The dashboard shows each window's countdown and the absolute reset time in the viewer's local time (for example `resets in 3h 47m (Tue, Nov 24 12:20 AM)`); `aao collect quotas` prints the same per window. Screen-format, login, and cleanup failures appear in Collector messages; they never become guessed quota values.
- **Kiro** uses its built-in `/usage` in `kiro-cli chat`, reporting monthly credits used out of the plan allowance and the displayed reset date. **Antigravity** uses [`/usage`](https://antigravity.google/docs/cli/commands/usage/), reporting weekly and five-hour remaining quotas for Gemini and Claude/GPT, plus the separate Argon weekly quota when present. The reader scrolls the panel using only the keys in `agents.json` `quota_screen.read_pages`, merges windows by name and model group (a scrolled page whose group heading is off-screen is identified by its "Models within this group:" line; a later page that stays unreadable ends the read with the pages already read instead of timing out), and never sends a model prompt. Both readers are included in the default screen fallback list.
- **Cursor** uses the built-in `/usage` command in the installed CLI. Its Included percentage is the billing-cycle quota; Auto and API are breakdowns of that same allowance and are not counted as separate quotas. A bounded On-Demand dollar allowance becomes a separate scoped window; disabled, unavailable, or unlimited on-demand usage is not converted into a quota percentage. This command was verified against the installed CLI and its actual screen, even though the public command list omitted it.
- **Muse** (web subscription, no CLI) is read from the site's own **Settings → General → Usage** panel in the saved `muse` browser profile by `web_muse.quota()`, also run as `uv run aao web quota muse [--json]`. The page loads that panel with a Next.js server action whose response holds a `subscription` object; the reader opens Settings in a new tab of the Muse browser, catches that response (the action id changes with each deployment, so it is never called directly), and falls back to the dialog's text. It reports the plan's **weekly** window (`percentUsed`, `resetsAt`) and the never-expiring **additional tokens** top-up as a window with `used`/`remaining`/`limit` in the site's raw units plus the site's own label (for example "10B tokens left") as the card's balance. A `quotaStatus` other than `SUFFICIENT` appears as the card's error. The read is deterministic, never clicks **Upgrade** and never types a password; a signed-out profile is reported as an error (log in with `aao web login muse`). When the Muse browser is not already open the collector opens it headless and closes it again; an open one is reused without touching its page. `AAO_QUOTA_WEB_TARGETS` lists the web readers (default `muse`, `none` disables them); a target with no saved profile is skipped.
- **Quotas tab layout.** A top bar, **Next weekly and monthly resets**, lists the three soonest weekly, monthly or billing-cycle resets across every account: a days-and-hours countdown, the local reset time, the share still left to use, and that share's dollar value. `AAO_QUOTA_PLAN_USD` (`provider=monthly USD`, optionally `provider:account=…`) sets each plan's price; the collector copies it onto the account as `plan_usd_month`, and the dashboard divides it by 52/12 into a weekly value so weekly and monthly windows sit on the same per-week scale (`≈ $X of $Y/week still unused`). A price of 0 shows as a free plan (Copilot Free, Muse Free). A credit-metered plan with no price (Kiro) is valued in its own credits instead: credits still unused out of the plan allowance, and the allowance per week (`≈ 227 credits of 5,000 still unused (1,154/week)`). Any other provider without a price says so instead of guessing. Below the bar, each card shows the numbers and the reset wording exactly as the app reported them (`reset_text`), falling back to the parsed time only when the app gave no wording.
- External quota subprocesses omit `SSLKEYLOGFILE`, matching the repository HTTP client's workaround for Windows monitoring pipes. No credentials are changed or refreshed by the orchestrator.
- Every collection appends to `state/quota_history.jsonl`; the run-out projection is a linear fit over snapshots of the *same* window period (same `resets_at`) and warns when 100 % would be reached before the reset.
- quota's herdr plugin (`external/quota/herdr-plugin`) can show the same numbers in the herdr sidebar per pane.

## Token usage and API-equivalent cost

Every row is (agent, session, model, day) with tokens split the way API pricing is: non-cached input, cache write 5 m, cache write 1 h, cache read, output (reasoning counted inside output).

| Agent | Log | Gotchas |
| --- | --- | --- |
| Claude Code | `~/.claude/projects/*/*.jsonl` | one line per content block repeats the same usage: dedupe by (message id, request id); `cache_creation` gives the 5 m/1 h split; `usage.speed == "fast"` marks fast mode |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` | `token_count` totals are cumulative and re-emitted on rate-limit updates: count only increases; `input_tokens` *includes* `cached_input_tokens` |
| OpenCode / Kilo | `~/.local/share/{opencode,kilo}/*.db` (SQLite, read-only) | `reasoning` is separate from `output` and billed as output |
| GitHub Copilot | `~/.copilot/session-state/*/events.jsonl` and `~/.copilot/session-state/*.jsonl` | one `session.usage_record` per model call; `inputTokens` *includes* both cache reads and cache writes (checked against `session.shutdown` `tokenDetails`), output includes reasoning; writes with `cacheTtlSeconds` ≥ 3600 are long-TTL. Older sessions have only `session.shutdown` `modelMetrics`: each shutdown is one run unless it is a running total (premium requests and every count grew), then only the increase counts. Subagent records appear once, in the session that logged them |
| Kiro | `~/.kiro/sessions/cli/*.json` (`user_turn_metadatas`) | the CLI writes **zero** token counts, so Kiro rows carry requests (`total_request_count`) and metered **credits** (`metering_usage`) only, no tokens and no API-equivalent cost; `auto` routing is the model `kiro/auto`. Token counts are used if Kiro ever fills them in |

Rows also carry `requests` and `credits`. Rows with no tokens are cost 0 (`price_source: no-tokens`), never listed as unpriced. The dashboard shows a Kiro credits tile and Requests/Credits columns when any credits are present.

**Pricing mechanics** (learned from ccusage and Splunk Token Meter):

1. `data/api_prices.json`: committed per-model prices with `effective_from`, maintained by a **script, not an LLM**: `uv run aao prices update` (`src/orchestrator/price_update.py`) fetches the official pricing pages as Markdown and parses them: Anthropic, OpenAI, Google Gemini (including its announced future price dates), xAI, Z.ai. It runs daily in `.github/workflows/update-prices.yml` and opens a PR on change. A price change is a **new entry**, never an edit, so history keeps the price in force on that day; unchanged prices only move `verified_at`. If a page's layout changes, the parser reports "found no prices" and fails the job rather than writing guesses. `cache_write_5m` / `cache_write_1h` hold the provider's short/long-TTL cache-write price (OpenAI: 30 min / 12 h); providers without a write fee bill writes as input. `fast_multiplier` prices fast mode; `aliases` cover same-priced ids. DeepSeek (HTML only, peak/off-peak), Kimi and Qwen have no machine-readable official page and use the LiteLLM fallback.
2. LiteLLM's public price list (`uv run aao prices sync` → `state/litellm_prices.json`) for anything not in the table. It lists models under resellers too, so lookup prefers the bare key, then the row's own provider prefix, then a lab's first-party API. LiteLLM has no price history: it is the current price.
3. Routes marked `-free` / `:free` cost 0. Anything else is **unpriced** and listed on the dashboard; add it to the table.

Costs are computed at read time, so fixing a price re-prices history without rescanning. Cost is what the tokens *would* cost at API list prices; subscription usage is not billed this way, which is the point: it shows what each plan is worth.

## Free tokens

`data/free_tokens.json` (schema `free-tokens-v1`) lists free tiers, credits, promos and free model routes the agents in `agents.json` can use. Each source: `id`, `provider`, `offer`, `kind` (free-tier, daily, weekly, monthly, one-time, trial, promo, referral, credits), `amount` (as the provider states it), `agent_ids`, `access` (cli/web/api/ide/desktop), `url` (official, https), `expires`, `status` (active/expired/unverified/ended), `verified_at`, optional `how_to_claim` and `notes`. The dashboard flags the list as stale after 36 h.

Free offers need judgment (reading announcements, spotting expiry), so a daily LLM agent maintains this file: [prompts/daily_data_update.md](../prompts/daily_data_update.md).
